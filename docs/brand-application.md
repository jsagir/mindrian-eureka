# M:OS brand application for Eureka

## Work record

- **Consumer:** MindrianOS Eureka README redesign (`mindrian-eureka-readme`)
- **Relationship:** Eureka is an adjunct intelligence service for MindrianOS.
- **Job:** When a MindrianOS user or developer arrives to understand how Eureka explores uncertainty, show the service's role, the right CLI or MCP entrypoint, and its limits so they can choose a grounded next move.
- **Source:** M:OS design system 2.7.0 at source commit `8d07e4f8b30f784c5794df050321c62c649ef7d2`, private [`mos-brand`](https://github.com/jsagir/mos-brand) repository, family architecture, logo system, color, typography, and documentation guidance.
- **Intake:** Routed by the brand system's `npm run intake` command. The source generated 27 context, dependency, and task routes. The [validated use packet](brand/mindrian-eureka-readme-use-packet.json) records that route. The generation used a local source checkout and is not a registration in the M:OS runtime or family registry.

## Adopted workflow

1. **Brief:** State the reader, service relationship, JTBD, supporting evidence, and selected brand guidance before changing a surface.
2. **Produce:** Keep Eureka's name, job, CLI/MCP identifiers, and maturity distinct. Use the canonical parent logo unchanged in a separate endorsement position. Inherit the shared palette, typography, evidence distinctions, language rules, and documentation conventions.
3. **Review:** Check navigation and local links, preserve technical facts and readiness labels, and record logo provenance. Do not claim runtime integration or visual review that did not occur.
4. **Return learning:** Record product-boundary questions and any requested family identity decisions here and in the relevant repository issue or decision record.

## Application decisions

- The README gives **MindrianOS Eureka** the title position and describes it as an adjunct intelligence service.
- The tagline is **“Extracting opportunities hidden in plain sight.”**
- The exact M:OS parent lockup is an endorsement, not a replacement Eureka wordmark.
- The Wicked Problems Theo face identifies the inquiry context. It is not the parent logo, an operational status, or evidence that a wicked challenge was solved.
- The README's repository instructions remain direct and technical. The MindrianOS host retains room context, approval, external research, Theo calls, and portfolio decisions. The Eureka/MindrianOS adapter remains outstanding until implemented and verified.
- Final registration of Eureka as a family member, its distinct signature mark, and any changes to the parent brand system remain separate brand-governance decisions. This README does not imply that registration.
