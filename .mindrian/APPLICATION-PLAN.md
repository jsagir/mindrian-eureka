## Walk the rooms

Every route above is an ICM segment with the same five files. Walk them in order and stop when the job is served: ROOM.md names the one job; INDEX.md routes to a smaller segment or to an artifact; CONTEXT.md states inputs, process, outputs and the human check; STATE.md gives status and artifact count; the dated entries hold the canonical artifacts. Read a direct segment in full, an inherited segment for its constraints only, an adjacent segment within its declared scope, and the baseline always. The process in CONTEXT.md is the production procedure for that part of the work; the human check is its acceptance test and belongs in the review stage of the run, quoted, with evidence. A thin segment (two artifacts or fewer) is applied through the voice, the positioning and the stops, and the gap is named for the book; it is never filled with an invented rule.

## Folder workflow

1. Brief: identify the actual deliverable and reader progress. Read the smallest contract, its inherited constraints and relevant adjacent dependencies. Answer missing meaning questions before selecting a tool or template.
2. Produce: use tools check/install/prepare for applicable blogs, images, visual aids or animation. Apply the returned instructions before creating. Put work in the current numbered run output.
3. Review: check the actual deliverable against the selected contracts. Record sources, checks, uncertainty and the actual reviewer. A tool result is not human approval.
4. Return learning: record what worked, what failed and a bounded proposed improvement. Consumer learning cannot silently alter canonical brand rules.

## Keep the route current

Before a new piece or material revision, run mos-brand doctor. It compares against the installed source, not the remote repository. Update the private package deliberately to receive upstream changes, preview mos-brand refresh, then apply reviewed changes and run doctor again. Local managed edits remain protected; copied assets and historical runs are not silently rewritten. Reconfigure when surfaces, language, family identity or workflow scope changes.

Never reinterpret an old reviewed run under a new source version. Start a new run after a source or scope change. No automatic background update or remote-version monitoring is implied.
