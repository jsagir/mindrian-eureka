<objective>
Show a person how to start a room from a pair (D-04, SEED-05). Under each pair in the bank the hub prints the exact seed command for that pair as text to copy. The page stays static and offline. It runs nothing.

Purpose: the person who finds a pair in the hub should reach a seed in one paste, without reading a guide. Plan 02.3-02 made `eureka seed <run> --pair <id>`. This plan names it where the pair is.

Design rules. D-04 says: reuse the chip and label components, no new visual design, and `mindrian-job-ux-ui` rules the row. The only new CSS is the selector that gives the new row the full width. A row that carries the class `hub-bank-labels` would be placed in the same grid cell as the role labels (the bank CSS places every `.hub-bank-labels` at an explicit cell), so the seed row does not use that class. Observation for the owner: the Phase 2.2 extras row does use it, so it may overlap the role labels. This plan measures the new row only and records the extras row as a finding; it does not change it.

Scope: payload keys, copy deck, client row, no-script row, one CSS selector, the design record, tests. No change to the reader (plan 02.3-01 did that). No clipboard code, no button, no script that runs a command.

Output: 6 edited hub files, 2 doc edits, 1 new test file, 1 new browser check, 2 edited test files (one conditional), 3 task commits by explicit path, 1 summary. No push.
</objective>
