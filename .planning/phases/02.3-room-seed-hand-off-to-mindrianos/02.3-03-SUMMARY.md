# Phase 02.3 Plan 03: Cluster seed and candidate list Summary

**`eureka seed <run> --cluster <record-id>` writes a cluster seed (spine fills known and feed-next, one bank entry per paired neighbour, evidence for every record) and `eureka seed <run> --list` prints cross pairs, open-open pairs and spine records as counts and classes, with no value claim.**

## Accomplishments

- `seed.graph.build_pair_graph` merges both engines into one node per pair id; a pair id with different records or classes in the two engines raises a damaged-run error (fix `Run eureka run again.`).
- `seed.candidates` orders pairs by degree sum then ids, spines by degree then record id. A run without classes lists all pairs in one group `Pairs (no class)`. Pairs of class licensed_licensed are in no group.
- `builder.build_cluster_seed` reuses `assemble_seed` and `_bank_entry`. In a cluster the statement draft names the spine as `tech_a` and the neighbour as `tech_b`. Output of `build_pair_seed` is unchanged.
- `command.py` takes the selector group `--pair | --cluster | --list`, `--min-degree` (1 to 1000, default 3) and `--limit` (0 to 10000, default 25). `--out` with `--list` and `--min-degree` with `--pair` are usage errors. The `--list` branch does not import `StagedRun` and writes nothing.
