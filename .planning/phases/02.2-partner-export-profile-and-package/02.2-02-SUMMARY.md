# Phase 02.2 Plan 02: Text side-car join, partner run guide and partner-internal ruling Summary

**`eureka run --mapping <file> --text-sidecar <file>` appends side-car text to thin CSV records joined on the raw case number, prints 1 coverage line in 4 numbers, records the side-car sha256 and the counts in the manifest; a run without the flag writes the same bytes; the one-page partner guide and the dated partner-internal ruling are recorded while public distribution stays no-go.**

## Accomplishments

- `--text-sidecar FILE` sits after `--mapping` in `eureka run --help`; `build_run_request` refuses it without `--mapping` (`UsageError`, exit 2, fix text); `RunRequest.text_sidecar` is set from the flag; `_validate` refuses a path that is not a file with the file name only.
- `load_text_sidecar` reads a `.csv` (first column id, column `text`) or a `.json` object through `_read_file`; ids and texts pass `normalize_text`; blank rows are skipped and counted; duplicate ids are a `RunError` with the count only; other suffixes, a CSV without `text`, and a JSON document that is not an object of strings are `UsageError`s with a fix.
- `_discover(..., exclude=)` skips the side-car by resolved path, so a side-car inside the input folder is not read as a second CSV (`input_files` holds `recs.csv` only; corpus digest equal to the outside case).
- The join runs inside the drop loop on `_Candidate.raw_id` (the id cell before `_sanitize_id` and before the `id_base/` prefix), only when the own text is under `MIN_BODY_CHARS`; the text is `own + "\n\n" + sidecar` (or the side-car text when own is empty); `text_source` is `sidecar`; `text_sha256` hashes the final text.
- `Corpus.text_coverage` and `Corpus.text_sidecar` feed `manifest_corpus()["text_coverage"]` and `manifest_inputs()["text_sidecar"]` (sha256, bytes, records, matched, unmatched; no path). `RunSummary.lines()` prints `Text coverage: N records, N with own text, N filled from the side-car, N still thin and dropped` after the `Records:` line, also on a dry run; `to_json_dict()["counts"]["text_coverage"]` holds the 4 keys.
- `docs/partner-run-guide.md`: 10 headings in the D-05 order, JHTV only, no person, no em or en dash, `candidate, not verified` on every result sentence, the exact run and hub commands, the coverage line with slots, the 3 pair classes, the hub filter options of plan 02.2-03, `MINDRIAN_EUREKA_ROOT` for the host.
- `docs/rs-release-gate.md`: 4 keys `partner_internal_decision: approve`, `partner_internal_scope`, `partner_internal_decided_on: 2026-10-29`, `partner_internal_decided_by` (same value as `decided_by`), and section 9; `decision: no-go`, `status: draft`, `reopen_when` G1 G2 G3 G5 unchanged. `docs/integrations/mindrianos.md` gains 1 cross-link sentence.

## Decisions Made

- `matched` counts side-car ids that equal the raw id of any candidate, thin or not, so a side-car keyed by the wrong column is visible as `unmatched == records`.
- On a Markdown-only input the specific warning `The side-car matched no record. The input holds no CSV record id.` is emitted alone, in place of the count warning.
- A CSV side-car whose first header is `text` is refused (the id must be first), with the headers listed and a fix.
- The duplicate-id error gives the number of repeated rows only; the JSON refusal names the file only (no document content).
- 3 task commits instead of 1 implementation commit (orchestrator objective: 1 commit per task). The plan's "HEAD lists exactly 9 files" check is met by the union of the 3 commits.
