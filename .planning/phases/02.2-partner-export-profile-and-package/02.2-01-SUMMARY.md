# Phase 02.2 Plan 01: Outcome rule, carry columns and pair classes Summary

**A mapping-driven outcome rule classifies every CSV record `licensed` or `open`, every pair of both engines gets `pair_class` plus the carried outcome cells, the run summary and manifest record the counts and the rule, and a run without a rule writes the same bytes as before.**

## Accomplishments

- `_ENTRY_SCHEMA` accepts `outcome_rule` and `carry_columns`; 8 wrong shapes are refused with a `UsageError` that names the file and gives a fix (`tests/test_run_partner_mapping.py::test_rule_and_carry_schema_refusals`).
- The shipped mapping `examples/mappings/technology-audit-export.json` loads; text columns are the 8 D-01 columns in order; `html` is `always` (entity-only abstract decoded, Pitfall 1); the 6 D-02 conditions and the 20 D-03 carry columns are present; no people, company-list, money or outcome column is in the text set.
- `_read_csv` evaluates the rule per row (strip and casefold for `equals`; `int()` for `greater_than` with blank or unparsable as 0 and 1 warning per column, counts only). Carried cells are trimmed raw strings.
- `build_corpus` warns in words when a class holds fewer than 2 records or when a cross pair is impossible, and clears the classes with a warning on a mixed corpus.
- `attach_pair_classes` adds exactly `pair_class`, `left_extras`, `right_extras` to every pair and `counts.pair_classes` to the file; called once per engine document in `_write_outputs`.
- `RunSummary` prints `<engine name> classes: cross N, open_open N, licensed_licensed N` per engine and writes `counts.pair_classes` in the JSON. The manifest records `settings.run.outcome_rules`, `settings.run.carry_columns` and `corpus.outcome_classes`.
- `ranked-pairs.md` gains a `Class` column and a `Classes:` line only when classes exist. The 7-column header of `tests/test_run_output.py:175` stays byte-identical otherwise.

## Decisions Made

- Every rule condition is evaluated on every row, with no short-circuit on the first match, so the per-column count warning reports every unparsable cell. Cost: 6 string compares per row.
- Class counts and the class-size warnings are computed on the kept records (after the cap), which are the records both engines score. `corpus.outcome_classes` therefore sums to `records_used`.
- The mixed-corpus guard runs on the usable list before the minimum-record check, then the class notes run on the kept list.
- 3 task commits (test, feat, feat) instead of the plan's 1 implementation commit, as the orchestrator objective asks for 1 commit per task. The plan's acceptance check "HEAD lists exactly 10 files" is met by the union of the 3 commits.
