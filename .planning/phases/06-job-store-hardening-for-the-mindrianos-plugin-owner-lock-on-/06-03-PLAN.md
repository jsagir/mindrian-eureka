<objective>
Give every job record one owner and an OS-level lock that the owner holds for the life of the job. A second opener gets a typed `owner_locked` result and changes nothing. The lock ends on the terminal state and when the owner process dies.

Purpose: the plugin keeps one engine process per job session and up to 8 sessions at once (`eureka-capability-jobs.cjs:17-19`), so several processes share one `jobs.sqlite3`. Today any process can cancel, read or recover any job (`jobs.py:185-193`, `:425-446`, and the recover rule of plan 06-02). Criterion 1 of the ROADMAP; it also narrows the recover rule of plan 06-02 (threat T-06-06).

Output: `tests/test_job_owner_lock.py`, the lock in `jobs.py`, one RED commit and one GREEN commit.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| second engine process -> shared `jobs.sqlite3` and `job-locks/` | Another live process must not drive, cancel or recover a job it did not start. |
| plugin host -> `job_id` argument | A host string becomes part of a file name; it is validated before any path is built. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-08 | Tampering | `request_cancel`, `transition`, `recover` | mitigate | the lock state is read before any write; `locked` returns `owner_locked` and writes nothing (Task 2 Steps 5 and 7) |
| T-06-09 | Spoofing | `owner_pid`, `owner_token` | accept | the row names the owner for reporting; the OS lock, not the row, decides ownership; a pid reuse cannot take a lock |
| T-06-10 | Tampering | `lock_path` | mitigate | `JOB_ID_PATTERN` before `Path` join; a bad id raises and creates no file (Task 2 Step 3) |
| T-06-11 | Information disclosure | lock files | mitigate | directory `0o700`, file `0o600` on POSIX (UNVERIFIED on Windows, documented) |
| T-06-12 | Denial of service | active count | mitigate | orphan rows do not consume the 8 slots (Task 2 Step 4) |
| T-06-SC | Tampering | npm/pip/cargo installs | accept | no package-manager install task; standard library only (D-09) |
</threat_model>
