<objective>
Write the front-end base: the stylesheet and the core script that every view module plugs into, with static rule tests and browser tests.

Purpose: HUB-01 (the three views work from a local file), HUB-02 (book tokens, type, layout, motion and Theo face states are implemented as ruled) and HUB-03 (the status label and source link rules hold on the shell). Plans 11 to 15 add one view or one feature each, and plan 18 adds the 3D stage, through the API defined here.

Locked decisions this plan implements:
- D-04: shared selection and filters across views; the page title and h1 are the view question; the bank is the first view.
- D-10: colour meaning from the book; the palette is the only source of colour.
- D-13: hard edges stay on panels and controls (`--mos-radius:0`).
- D-15: the data check panel is on every view, quiet, from the run only.
- D-16: tokens from the book file; 12-column grid with 24 px gutters, 1200 px inner maximum; tablet 6 columns; phone 4 columns with 20 px outer gutters and 16 px column gap; 4 px spacing steps; logical properties; cards only for bounded objects.
- D-19, D-20: copy from the deck; the Theo face state follows the UI-SPEC table in section 10; the parent lockup is never restyled.
- D-21: no ambient motion; motion only on a person's action; none under `prefers-reduced-motion`.
- D-22: WCAG 2.2 AA; 44 px targets; 3 px focus ring; 13 px label floor (a failure only below 13 px at 1024 px and up); 320 px reflow; text and lists work without JavaScript. The hub applies 13 px at all widths. The book fails only below 13 px at 1024 px and up. Stricter by choice, proposed segment (register item 10).

Extension API (the contract of plans 11 to 15 and 18). `window.HubApp` is created by hub-core.js. Members: `data` (the payload after start); `copy` (HUB_COPY); `fmt(id, values)` fills a deck string (throws on an unknown id or a missing value); `el(tag, attrs, children)` builds an element with text only (never HTML), accepts only a fixed list of attribute names, and rejects an `href` or `src` that starts with a scheme or a double slash; `state` (view, selection, filters with engine, weak, query, file and inPair, panelOpen); `registerView(name, {render(container), onEvent(name, detail)})`; `registerPanel({show(selection, opener), hide(), isOpen()})`; `select(selection, opener)` where selection is `{type: 'record', id}` or `{type: 'pair', key}`; `clearSelection()`; `setFilter(name, value)`; `on(event, fn)` and `emit(event, detail)` for the events `start`, `view`, `select`, `clear`, `filter`; `go(view, options)`; `search(query, limit)` returning record ids; `motion` with `reduced` (boolean) and `ms(tokenName)` (reads the CSS token, returns 0 when reduced); `index` with Map objects `records`, `pairs`, `hoods`; `notice(text)` writes into the polite live region of the page; `start(payload)`.

Shared CSS vocabulary (classes later plans use): `hub-button`, `hub-button--quiet`, `hub-link`, `hub-chip`, `hub-role` with the modifiers `hub-role--source`, `hub-role--inferred`, `hub-role--proposed`, `hub-role--bridge`, `hub-flag`, `hub-panel`, `hub-quiet`, `hub-field`, `hub-row`, `hub-row--selected`, `hub-score`, `hub-mono`, `hub-visually-hidden`, `hub-evidence`, `hub-skip`, `hub-error` (red heading and a 3 px red rule on the inline-start side, on paper or white only).
