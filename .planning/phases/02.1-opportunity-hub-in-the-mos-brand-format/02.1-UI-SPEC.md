# Phase 2.1 - UI Design Contract: Opportunity Hub

> Visual and interaction contract for one local page with three views. Written by gsd-ui-researcher from CONTEXT.md decisions D-01 to D-23 and the mos-brand book. Verified by gsd-ui-checker. Visual verification pending: nothing in this file has been rendered or screenshot yet.

## How to read this file

- The book is the only design authority. No shadcn, Tailwind, component library or outside design system is used.
- Every value below is copied from a book file or from CONTEXT.md. Book paths are relative to `~/mos-brand/segments/` unless they start with `references/`.
- Where the book says nothing, the text says "book silent, proposed segment". Section 16 lists every such gap in one place for return to the book (D-03).
- The mos-brand CLI is blocked in this repo until the intake runs (D-01). Plan 1 must confirm each ruling here with `mos-brand context` and `mos-brand review`.
- Two items are OWNER-WORD and use their stated defaults. They are marked "default, owner may override": D-14 (the "Potential eureka" chip) and D-17 (the password gate).
- Hard stops for all page text: no em dashes, plain English, never an internal engine abbreviation, every number sourced or absent, the label `candidate, not verified` on every claim and opportunity, no network call.

Rules:
- Five sizes are declared: 40/28, 22/20, 18/17, 16 and 13. The book defines body (18) and UI (16) as separate roles, so the checker's "3 to 4 sizes" guidance is exceeded by one. This is a book-ruled exception, not a choice.
- Three weights are used: 400, 600, 700. The book gives 700 for display, 400 for body and 500 to 600 for UI. The hub uses 600 for UI (matches `.mos-button` in the token CSS).
- `font-synthesis: none; font-optical-sizing: auto;` (typography segment). No italics (no italic files are bundled).
- Minimum label size is 13 px everywhere. The graph guide says 12 px (section 7) and the accessibility ruling of 2026-10-23 says 13 px caption floor. The hub uses 13 px, which satisfies both. The reference template's 12 px labels are not copied.
- Measure for reading prose: 58 to 72 Latin characters (typography segment). The reading panel at 400 px with 20 px padding gives about 45 to 50 characters, which is acceptable for a side panel (book silent on panel measure, proposed segment).
- Mono IDs sit inside `<bdi>` so mixed-direction text stays isolated later (`experience/accessibility` review list).

Source: the `HOOD` list in `network.template.html`. Tints are decoration. A neighborhood is always also named in words ("Neighborhood 3"), never by tint alone.

## 6. The three views

One page. One shared selection (a record, or a pair). Switching view keeps the selection, the open panel and the filters. Views are reached by links to `#bank`, `#graph`, `#catalogue`. A record deep link is `hub.html#RECORD_ID` (D-04, graph guide section 6). If a record ID equals one of the three view names, its deep link is `#record:ID`. The book is silent on this collision (book silent, proposed segment).

On a view change, the H1 text and `document.title` change to that view's question and focus moves to the H1 (`tabindex="-1"`). Only one H1 exists at a time. The graph guide asks for the page title to be the question; this keeps that rule per view (book silent on a multi-view page, proposed segment).

Without JavaScript (ungated build only): all three sections are in the HTML in the order bank, graph, catalogue. The graph section shows the list of pairs instead of the map. Every control that needs JavaScript is absent, not disabled. A `noscript` line says so (G12).

Stage rules:

#### 6.2a Small collection: static diagram

Shown when fewer than 15 records are in a visible pair. SVG, no library. Records are circles (radius 12) placed on one circle in order of neighborhood then ID. Pairs are straight dashed chords (7 on, 8 off at the specimen scale, stroke 2) in cobalt, each named in the legend by the word "Proposed". Each circle carries its ID in 13 px mono beside it, with a paper halo for contrast. Circles are buttons that select the record. The diagram is a complete readable still with the pairs list beneath it. Heading text: Gr10.

#### 6.2b Data check panel (D-15, guide section 4)

Quiet panel (`--mos-quiet`, 1 px ink frame) below the map and the lists, on every view. It states, from the run only:
- records that share identical text with another record (count, hash match on `text_sha256`);
- records with no text (count);
- records removed before ranking and why (from the manifest corpus section);
- shared boilerplate families: shown only if the run provides them. The run does not provide a detector today, so the line reads "not checked in this run" (Gr/D lines in the copy deck). The hub does not invent a detector.
It never recomputes a score. A pair that involves an identical-text or no-text record shows a red-text flag (red on white or paper only).

Weighted label propagation over pair links. Weight = rank score of the pair, normalized within its engine to 0 to 1 (plan must state the rule and record it). Ties are broken by record ID. No random values. Same run folder gives the same neighborhoods byte for byte (D-07).

### 7.5 Cut-offs (D-11)

Pairs below each engine's named cut-off are hidden by default. Both cut-offs are printed on the page in the bank and the graph guide. ## 12. Password gate (D-17, OWNER-WORD, default, owner may override)

Option `--password-env NAME`. Without the option the page is not gated and this section does not apply.
- `hub-data.js` carries an AES-GCM encrypted payload. Key = PBKDF2 of the passphrase. Salt and iteration count are stored in the file. The passphrase is read from the named environment variable at build time and is never written to disk or printed.
- The HTML of a gated build contains no record text, no title, no ID, no count. It contains the locked screen only.
- The page shows the locked screen until the payload decrypts. A failed decrypt shows L05. A missing `crypto.subtle` shows L06. A payload whose tag fails shows L05 (it cannot tell a wrong passphrase from a changed file); a payload that fails to parse after decrypt shows L08.
- No attempt limit exists because the file can be copied. The page does not claim one.
- L07 is shown on the locked screen. The README and the design-decisions file say the same thing in plain words: it protects the file at rest, not a machine that already holds the passphrase.
- Field: `type="password"`, `autocomplete="off"`, 44 px high, visible label, Show/Hide toggle as a 44 px button. Enter submits. Focus starts in the field.
- On success: store nothing (no localStorage, no cookie), render the hub in memory, move focus to the H1.
- WebCrypto availability from `file://` differs by browser: UNVERIFIED. Test in Chrome, Firefox and Safari (section 15).
- The book is silent on a password gate (book silent, proposed segment). The Theo Boundary state and the "Entrance gate" layout role (an open architectural threshold) apply; this gate is a real block, so it uses the strong frame of the "Human decision" role: 1 px ink frame, white plane, one primary action.

## 13. No-network contract (HUB-01, HUB-04)

- The page loads only its own files by relative path: HTML, CSS, JS, `hub-data.js`, fonts, SVGs, the vendored library.
- No `fetch`, `XMLHttpRequest`, `WebSocket`, `sendBeacon`, `<link rel=preconnect>`, remote font, remote image, analytics, Clarity snippet or CDN. (The MindrianOS rule that public pages carry a Clarity snippet does not apply: this is a local file page and the phase forbids any network call.)
- Optional hardening, to be tested before it ships: a `Content-Security-Policy` meta tag with `default-src 'none'` and `connect-src 'none'`, allowing only the local script, style, font and image sources. Behavior of `'self'` on `file://` differs by browser: UNVERIFIED.
- The static test cannot scan the vendored bundle for the text `http://`, because namespace strings such as the SVG namespace are not loads. Use two tests: (1) a source scan of the files the hub writes, for `src`, `href`, `srcset`, `url(`, `@import`, `fetch(` and `import(` that point at `http:` or `https:`; (2) a headless browser run with all non-`file:` requests blocked that fails on any attempted request.
- Every link to a source record is relative. A link to an outside web page is never rendered (the template's "Open the JHTV catalog record" link is not copied).
