# Phase 2.1 Plan 14: Password gate

**An optional password produces a data-free locked page and deterministic authenticated payload, which unlocks in memory in Chromium and Firefox.**

## Accomplishments

The gate uses the specified SHA-256 salt context, PBKDF2-SHA256 with 600000 rounds, keyed nonce context, AES-256-GCM and fixed associated data. Python imports the approved optional library only inside gate use. A frozen known-answer vector, repeat-build checks, changed-password/data checks, malformed-header controls and nonce regression checks cover the implementation.

The CLI accepts only --password-env with a validated variable name. Missing and empty values produce usage errors; the value is excluded from request repr, messages and output. Abbreviation is disabled so --password cannot become a value-taking alias. Short passphrases receive the specified constant warning. No new dependency was downloaded.

Gated exports use window.HUB_ENVELOPE and render no collection fields or counts into the locked HTML. The manifest omits counts but retains its required opaque source-manifest hash. Unlock uses browser WebCrypto and no storage, cookie or history write. Wrong password and changed authentication data use L05, unavailable WebCrypto uses L06, and authenticated malformed payload uses L08 with the Limit face. Success clears the input, starts the shared app and focuses the h1.

## Deviations from Plan

The plan simultaneously requires manifest.run.manifest_sha256 and says the fingerprint is absent from every file. The manifest keeps its required provenance hash; collection counts and readable source fields are excluded. The gate record states the resulting same-run linking risk.

Random base64 ciphertext can contain URL-like slash sequences. The existing raw scanner produced a demonstrated false positive. The scanner now recognizes only complete passive HUB, HUB_ENVELOPE and HUB_COPY JSON assignments and validates relevant source paths. Appended executable code, malformed JSON, non-finite JSON values and nonlocal source paths still fail negative controls. Opaque ciphertext is not scanned as executable JavaScript or visible copy. This required the small sibling scanner change.

Arbitrary record IDs can coincide with fixed chrome. Privacy checks use distinctive identifiers and source text plus identical locked HTML across different runs, rather than asserting that a short ID substring can never occur in a fixed label.

## Unverified and Risks

The deterministic nonce derivation is custom and has no independent security review. The nonce regression check is not a proof of collision freedom. Repeated runs expose equality and the public run hash, length and derivation data enable offline passphrase guessing and some same-run precomputation reuse. The gate record explains these limits and links the primary API documentation.

Original run folders, source files, old exports, backups, terminal summaries and a machine already holding the passphrase remain outside this protection. Clearing an input does not prove secure memory erasure. Browser code is not authenticated by this envelope. Installed cryptography is 46.0.3 within the approved range; the lock names 50.0.2. Safari, screen-reader behavior and owner brand approval remain unverified.
