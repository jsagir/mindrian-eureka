    Per D-12, D-21, D-22 and UI-SPEC section 13. The driver is a test helper in this Python repo. Do not add a package.json, node_modules or any npm install: the driver gets the Playwright path as an argument.

    1. tests/hub_browser/driver.cjs (CommonJS, no dependencies besides the Playwright module). Arguments: `--playwright DIR` and `--scenario FILE`. It prints exactly one JSON object to stdout and exits 0, even when a page check fails (failures are data). It exits 2 with a plain message on stderr only for driver errors (bad arguments, browser cannot start).
       Scenario keys: browser (`chromium` or `firefox` or `webkit`), url (a file URL, optionally with a hash), viewport (width, height), reducedMotion (boolean), forcedColors (`active` or `none`), javaScript (boolean, default true), webgl (boolean, default true), blockNetwork (default true), initScripts (list of file paths run before page scripts), timeoutMs (default 30000), steps (list).
       Step kinds: goto, click, fill, press, hover, focus, wait (ms), waitFor (selector), waitForFunction (file path of a script body), setViewport (width, height), reload, screenshot (path, fullPage), dom (as, optional path: write the document element outer HTML), eval (script file, as, optional args object). An `eval` script file holds the body of an async function with one parameter `args`; the driver wraps it as an async function expression and passes it to `page.evaluate` as a function with the args object (this runs through the protocol, so a page Content-Security-Policy cannot block it). Its return value (JSON) is stored under the name in `as`.
       Network rule: every request whose URL starts with http, https, ws, wss or ftp is aborted and recorded in `blockedRequests`. Use `context.route` with a function matcher and `context.routeWebSocket`. Record file, data and blob requests in `localRequests` (names only, no query). Record `console` messages (type and text), `pageErrors`, and `cspViolations` (collect `securitypolicyviolation` events with an init script that pushes them to `window.__csp` and read them back at the end).
       Browser options: for WebGL on, Chromium gets the arguments `--use-gl=angle`, `--use-angle=swiftshader`, `--enable-unsafe-swiftshader`, `--ignore-gpu-blocklist`; for WebGL off, Chromium gets `--disable-gpu`, `--disable-3d-apis` and Firefox gets the preference `webgl.disabled` true. Context options: viewport, `javaScriptEnabled`, `reducedMotion` (`reduce` or `no-preference`), `forcedColors`, `serviceWorkers` set to `block`, `acceptDownloads` false, `locale` `en-US`, `timezoneId` `UTC`.
       Result object keys: browser, version, ok (true when all steps ran), results (name to value), screenshots (list), blockedRequests, localRequests, console, pageErrors, cspViolations, stepErrors (list of step index and message).
    2. tests/hub_browser_support.py: `find_playwright() -> Path | None` (order: env EUREKA_PLAYWRIGHT_DIR; `npm root -g` plus `/playwright` with a 10 second timeout; ~/.npm-global/lib/node_modules/playwright; a path counts only if it holds package.json); `file_url(path, fragment="") -> str`; `run_scenario(scenario: dict, timeout: int = 180) -> dict` (writes the scenario to a temp file, calls `node driver.cjs`, parses stdout, raises `BrowserToolError` with stderr text on exit code 2 or bad JSON); `require_browser(browser: str = "chromium")` which calls `pytest.skip` with a reason when the tool or the browser is missing and calls `pytest.fail` instead when the env var EUREKA_REQUIRE_BROWSER is "1". Also export a `BROWSERS` tuple of `chromium` and `firefox` for parametrize.
    3. Probe pages (plain HTML, no external resource): media.html writes one JSON line into `document.title` and into `window.__probe` with `prefersReducedMotion`, `forcedColors`, `webgl` (a canvas context test), `subtle` (`crypto.subtle` present), `secure` (`isSecureContext`), `js` true. negative-control.html tries `fetch` of `https://example.invalid/x`, an `img` with a remote `http://example.invalid/i.png`, a `link rel=stylesheet` to a remote URL and `new WebSocket('wss://example.invalid/s')`. The `.invalid` top-level name never resolves, so a leak is impossible even if the block failed. noscript.html shows a `noscript` element with the text "script is off" and a body text "script is on" written by a script.
    4. tests/test_hub_browser_probe.py (parametrize over BROWSERS; call require_browser): media page under reduced motion true and false; WebGL true by default and false when webgl is false; negative control reports at least 3 blocked requests (names from all four attempts except the WebSocket may differ by browser: assert the fetch, the image and the stylesheet, and the WebSocket when the browser supports routing it) and `ok` true; javaScript false shows the noscript text in the `dom` result; a viewport step changes `innerWidth`; an `eval` result round-trips an args object; a screenshot step writes a non-empty PNG; the driver exits cleanly when the page has a script error (pageErrors holds it). Add a unit test for `find_playwright` order using monkeypatch of the env and of `subprocess.run`, and for `require_browser` with the env var set to "1".
    5. Do not commit screenshots or temp files. Use tmp_path.

    Per D-17 and UI-SPEC sections 12 and 13. These probes answer two questions with evidence: (1) does a ciphertext made in Python decrypt with WebCrypto on a file URL? (2) which Content-Security-Policy string lets the local files load and blocks everything else on a file URL?

    A. WebCrypto interop probe. In the test, generate a salt and a key with `hashlib.pbkdf2_hmac("sha256", passphrase, salt, 600000, dklen=32)`, a 12-byte nonce, and encrypt a short known JSON text with `cryptography`'s AESGCM (the output is ciphertext followed by the 16-byte tag, which is the layout WebCrypto expects). Use associated data equal to the ASCII text `eureka.hub-envelope.v1|600000`. Write a probe page into tmp_path that holds the base64 values and a script file that imports the passphrase as a raw PBKDF2 key, derives an AES-GCM 256 key with SHA-256 and 600000 iterations, decrypts with the same associated data, and puts the plain text into `window.__probe`. Run it in Chromium and Firefox. Assert the plain text matches; assert a wrong passphrase and a changed ciphertext byte make decrypt fail with an error (not a wrong text). Use `pytest.importorskip("cryptography")` for the Python side. Also run the same page in WebKit through the driver and record the outcome (launch error or result) in the results file; do not assert on WebKit.

    B. CSP probe. Write probe pages into tmp_path from the same template with an external script file, an external stylesheet, one image, one font file declaration (a few bytes are enough, the request is what counts), and a remote `fetch`. Try these candidate policy strings in a meta tag, one page each:
      1. default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; font-src 'self'; connect-src 'none'
      2. the same with the scheme source `file:` in place of 'self' in the four source lists
      3. the same as 1 with `'unsafe-inline'` added to style-src
      4. no meta tag (control)
    For each browser record: script ran, stylesheet applied, image loaded, font requested, the list of CSP violation events (directive names), and whether the remote fetch produced a violation event. Decision rule: choose the strictest candidate for which script, stylesheet, image and font all load in BOTH Chromium and Firefox and the remote fetch is reported as blocked by the policy. If none loads everything, record "no CSP meta tag" as the decision and say that the static scan and the page-level request block are then the controls.

    C. Write docs/brand/hub-probe-results.md now with these sections, each with a line starting `Result:` and a line starting `Fallback:`: "Headless browser tool" (path, Playwright version, which browsers start, WebKit outcome), "WebCrypto on file URLs" (outcome per browser, the exact derivation used), "CSP on file URLs" (a table of the four candidates by browser, and one line `CSP decision: {the chosen string or none}`), "WebGL in headless browsers". Leave the three sections of Task 3 for that task. Use plain English, no em dash.
    D. Add the probe tests to tests/test_hub_browser_probe.py (A and B as parametrized tests; the CSP test asserts the decision rule on the data it collected and prints the table with `-s`).
