<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| run folder to reader | Files in a run folder may be edited, damaged or crafted |
| engine strings to page | Notes and readings come from engine output, not from the hub |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.1-09 | Tampering | Edited pair or corpus file | mitigate | Reader recomputes sha256 of each file it reads and compares it with the manifest. Mismatch is RunError. |
| T-02.1-10 | Tampering | Crafted manifest `outputs[].path` (absolute or "..") to read another file | mitigate | The reader opens only its four fixed names under the run folder and ignores other manifest paths. A test covers a crafted path. |
| T-02.1-11 | Information disclosure | Internal file names or unknown strings reach the page | mitigate | Notes that match INTERNAL_NAME are dropped and counted. `reading` must equal one of three fixed sentences or the load fails. |
| T-02.1-12 | Spoofing | A non-run folder passed as RUN_DIR | mitigate | `is_eureka_run_folder` gate, then schema ids of every file. |
| T-02.1-13 | Information disclosure | Copy deck or helper holds a literal dash or bare short code that later scans trip over | mitigate | Source files use escapes, tests scan the source files themselves. |
</threat_model>
