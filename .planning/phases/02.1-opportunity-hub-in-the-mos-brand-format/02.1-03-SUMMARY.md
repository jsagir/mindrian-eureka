# Phase 2.1 Plan 03: Hub package base Summary

**Hub package base: one contracts module, one copy deck for all 85 UI-SPEC copy IDs, a run reader that checks every file hash and never opens run-info.json, and a test helper that builds synthetic run folders without a model.**

## Performance

- **Duration:** about 15 min (start time was not recorded; taken from commit times)
- **Tasks:** 2 of 2
- **Files:** 8 created, 0 modified (one cosmetic format change to contracts.py inside the Task 2 commit)

## Accomplishments

- Task 1: `hub/contracts.py` defines schema ids, file names, `HUB_CONFIG`, the 21 neighborhood tints, `INTERNAL_NAME`, `has_dash`, `has_internal_name`, the run dataclasses, all payload TypedDicts, `is_hub_folder`, `deep_link` and `js_assignment`. `hub/deck.py` holds 173 deck strings that cover all 85 IDs of UI-SPEC section 9 (G01-G16, B01-B14, Gr01-Gr19, C01-C11, P01-P09, D01-D03, L01-L08, E01-E05), plus `fill()` and `deck_js_bytes()`.
- Task 2: `hub/reader.py` `load_run()` reads `manifest.json` and four fixed files, checks each hash, parses the corpus and both pair files, drops notes with an internal name and refuses unknown reading sentences. `tests/hub_support.py` builds run folders of any size with copies, empty text, hostile text, zero pairs, pairs below the cut-off and long text.
- The copy test reads the real UI-SPEC file, does not skip, and fails if any ID has no key or any deck key has no ID.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The plan's "eureka" rule contradicts the owner ruling D-14**
- **Found during:** Task 1
- **Issue:** The plan says the word eureka may appear only in G03 and G14. UI-SPEC 7.6 and CONTEXT D-14 (owner ruling 2026-10-24) require the chip and every bridge string to say "Potential eureka". UI-SPEC E02 also names the command `eureka hub`.
- **Fix:** The copy test removes three allowed phrases (the product name "MindrianOS Eureka", "potential eureka(s)", "eureka hub") and asserts no other "eureka" remains. It also asserts that the bridge strings (Gr03.eureka, Gr05.tour, Gr05.next, Gr14.bridge, Gr15, P06.eureka) all say "potential eureka".
- **Files modified:** tests/test_hub_copy.py
- **Commit:** 42667f2

**2. [Rule 1 - Bug] Escaping `{` and `}` over the whole JSON text would break the file**
- **Found during:** Task 1
- **Issue:** The plan says to replace `{`, `}`, `&`, U+2028 and U+2029 "inside the JSON text". A brace outside a string is JSON structure. Escaping it gives invalid JavaScript.
- **Fix:** `js_assignment` applies the escapes only inside JSON strings (a regex finds each string). The test asserts one structural `{` and one `}` remain for a one-object value and that `json.loads` returns the same value.
- **Files modified:** src/mindrian_eureka/hub/contracts.py
- **Commit:** 42667f2

**3. [Rule 2 - Missing critical] `<` and `>` were not in the escape list**
- **Found during:** Task 1
- **Issue:** The plan's goal is that the file can never close a script element. The sequence that does that needs `<`. The listed characters do not include it.
- **Fix:** `<` and `>` are escaped as `<` and `>` inside strings. The test checks that `</script` never appears. `json.loads` returns the same data.
- **Files modified:** src/mindrian_eureka/hub/contracts.py
- **Commit:** 42667f2

**4. [Rule 2 - Missing critical] The reader checks more than the plan lists**
- **Found during:** Task 2
- **Issue:** The plan lists hash, schema and reading checks. A pair file under the wrong engine, a pair that names a missing record, a wrong pair count, a duplicate record id, a wrong record count in the corpus header, NaN in a number, and two manifest entries for one path with different hashes would all reach the page unchecked.
- **Fix:** Each case raises `RunError` with a fix line. Each has a test.
- **Files modified:** src/mindrian_eureka/hub/reader.py, tests/test_hub_reader.py
- **Commit:** 8fcc403

**5. [Rule 3 - Blocking] `SUMMARY_LINE` has no copy ID**
- **Found during:** Task 1
- **Issue:** The plan says to import `SUMMARY_LINE`. No UI-SPEC ID uses it, so the import fails the unused-import rule.
- **Fix:** `deck.py` imports `LABEL` and the two engine names only. The text of `SUMMARY_LINE` stays in the run folder report.
- **Files modified:** src/mindrian_eureka/hub/deck.py
- **Commit:** 42667f2

**6. [Rule 2 - Missing critical] Singular pair count**
- **Found during:** Task 1
- **Issue:** C06 gives the cell text "{n} pairs". For one pair this reads "1 pairs".
- **Fix:** Added the key `C06.one_pair` with the text "1 pair". The page code should use it when n is 1.
- **Files modified:** src/mindrian_eureka/hub/deck.py
- **Commit:** 42667f2
