# Phase 2.1 Plan 10: Shell and shared browser core

**A locally loaded shell with canonical book styling, safe shared state, accessible routing, and browser evidence.**

## Accomplishments

The stylesheet uses canonical tokens, the prescribed type roles and spacing, logical directions, square components, shared role treatments, 44 px control targets, a 3 px focus ring and reduced-motion rules. Static tests cover every authored stylesheet and classic script, including negative controls for small fonts, physical directions, forbidden APIs, colors, transitions and corners.

HubApp provides the planned extension API, text-only safe element creation, relative-link validation, Map indexes, stable search, shared filters and selection, panel hooks, events, notices, hash routing and motion preferences. Counts, copy, face states, status, data check, navigation and footer are sourced from the payload and copy deck. Unknown hashes preserve a usable view. Missing data or copy keeps the server lists available.

Browser checks cover five widths, both engines for behavior, no-JavaScript fallback visibility, errors, schema mismatch, reserved record IDs, source-string injection, copy provenance, keyboard focus, reduced motion, search and extension registration. Start is idempotent, and clearing a selection returns focus to its opener.

## Deviations from Plan

The browser driver needed a direct visible step because asynchronous page evaluation hangs in Firefox when JavaScript is disabled. An identified driver from that failed test was terminated. The replacement no-JavaScript tests pass in both browsers without enabling page JavaScript.

Large DOM snapshots also exposed truncated driver JSON: immediate process exit could precede stdout flush. The driver now awaits the write callback. The no-JavaScript DOM checks exercise this correction. No existing PLAN file changed.

Initial malformed or unknown record hashes now activate the default bank before routing; otherwise CSS could leave all views hidden. Two regression checks cover this case.

The Impeccable context launcher was not executable. Existing approved UI-SPEC, project context, canonical tokens and book layout, accessibility and typography references were used directly. No replacement design authority or extra context files were introduced.
