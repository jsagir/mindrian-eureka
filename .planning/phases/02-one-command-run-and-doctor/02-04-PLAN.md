<objective>
Build the output half of `eureka run`: project engine results to a fixed, timestamp-free shape with labels and plain-English readings (RUN-05), write every file through one canonical writer into a staging folder (RUN-04), and build the manifest and the separate run-info file (RUN-03). Add the small console helper for stderr and stdout rules.

Purpose: Success criteria 2, 3 and 4. Byte-identical ranked output needs the volatile fields kept out of every hashed file. The two engines use the same direction label with opposite meaning (research Pitfall 3), so the reading must come from the numbers.
Output: project.py, output.py, manifest.py, console.py and four test files. No model, no engine call, no network.

Locked decisions from 02-CONTEXT.md that this plan implements:
- "Run manifest fields: input file hashes, record counts, settings, seeds, library and model versions, output file hashes, caps hit."
- "Two runs on the same input give byte-identical ranked output" (RUN-04). The writer and the projection remove every known volatile field: runner.started_at, runner.finished_at, resource_use.duration_ms, metadata.generated_at, source_trail[].retrieved_at, the model path, room_dir.
- "Every output file carries 'candidate, not verified' and a score-meaning note" (RUN-05).
- "Works on a scratch copy of the input; never writes into the source folder": output goes to a staging folder next to --out; --out inside the input folder is refused.
- cli-developer: diagnostics and progress to stderr, results to stdout or files; no color when not a TTY; non-interactive.
- python-pro: full type hints, mypy --strict clean, ruff clean, dataclasses, pathlib, `X | None`, no bare except, Google-style docstrings, pytest fixtures and parametrize.
- OQ-4: the enclave OS is unknown. File modes use POSIX calls guarded for other systems (no failure on Windows).

Public API (plan 02-06 consumes these names exactly):
