<objective>
Build the clean corpus step of `eureka run` (RUN-02): read CSV and Markdown sources, assign stable record ids, normalize text, report every drop and every cap, hash every input file, and produce the corpus digest that goes into the manifest (RUN-03).

Purpose: Success criterion 1 (clean corpus with stable record IDs) and the input half of criterion 2 (input hashes, record counts, caps hit). The partner CSV headers are not known yet (shared-screen session 2026-10-27), so the CSV mapping is a small JSON file or flags.
Output: mapping.py, textclean.py, corpus.py and their tests. No model, no numpy, no network.

Locked decisions from 02-CONTEXT.md that this plan implements:
- "`eureka run` builds a clean corpus first with stable record IDs (what prepare_engine_corpus.py does for the JHTV run)." The generic builder ports the logic, not the JHTV data.
- "Works on a scratch copy of the input; never writes into the source folder." The builder is read-only on the input folder.
- Truncation and drops are reported in output and manifest, never silent (cap decision, OQ-3: truncate and report in caps_hit, do not refuse).
- "Design the CSV mapping so those headers can be dropped in without code changes" (CONTEXT, Specific Ideas).
- OQ-1: both engines score `title + "\n\n" + text`. Record.model_text carries the rule; the builder fills title and text separately.
- python-pro rules: full type hints, mypy --strict clean on the new modules, ruff clean, dataclasses, pathlib (no os.path), `X | None`, no bare except, no mutable defaults (use field(default_factory=...)), Google-style docstrings, pytest with parametrize.

Public API (plan 02-06 consumes these names exactly):
- mapping.py: `CsvMapping`, `MappingConfig` (with `.files`, `.sha256`, `.for_file(rel_path) -> CsvMapping | None`), `load_mapping_file(path: Path) -> MappingConfig`, `mapping_from_flags(*, id_column: str | None, title_column: str | None, text_columns: Sequence[str], source_column: str | None, delimiter: str | None) -> MappingConfig | None`, `skeleton_mapping(file_name: str, headers: Sequence[str]) -> str`.
- corpus.py: `build_corpus(input_dir: Path, *, mapping: MappingConfig | None, max_artifacts: int = MAX_ARTIFACTS) -> Corpus`. `Corpus` is a frozen dataclass with `records: tuple[Record, ...]` (sorted by id, after the cap), `input_files: tuple[InputFile, ...]`, `records_read: int`, `dropped: tuple[Dropped, ...]`, `caps_hit: tuple[CapHit, ...]`, `warnings: tuple[str, ...]`, `corpus_digest: str`, `folder_digest: str`, `mapping_sha256: str | None`, and two methods that return JSON-ready dicts: `manifest_inputs()` gives {"files": [{"path","bytes","sha256"}], "mapping_sha256", "folder_digest"}; `manifest_corpus()` gives {"records_read","records_used","dropped": [{"id","reason","source_file"}],"corpus_digest","caps_hit": [{"name","limit","records_in","records_used","dropped_count","dropped_ids_sha256"}]}.

Names used in prose: the unusual-pairs engine is "Find Unusual Pairs Across a Research Collection". The wording-and-meaning engine is "Rank Unusual Pairs by Wording and Meaning". Never write the short engine codes (regex \b(R[S]|H[S]I)\b) in a message the user can see.

Tooling for every verify command (user-level tools on PATH): `PYTHONPATH=src python3 -m pytest <files> -q -p no:cacheprovider`; `mypy --strict --ignore-missing-imports --follow-imports=silent --python-executable "$(command -v python3)" --cache-dir /tmp/eureka-mypy <new files>`; `ruff check --select E,F,I,UP,B --line-length 100 --no-cache <new files>`. Strict typing applies to new files only.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| input folder to corpus builder | File names, file content and symlinks are untrusted. |
