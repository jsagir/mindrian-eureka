<objective>
Build `eureka doctor` (DOC-01, DOC-02) and the shared model discovery that `eureka run` also uses. Add the mypy and ruff configuration, the check commands and a one-page offline install note.

Purpose: Success criterion 5. A non-author on a secure-enclave machine must see what is wrong and the exact command to fix it, before a run fails halfway. A missing model must be a loud, clear message.
Output: models.py, doctor.py, their tests, pyproject tool tables, CONTRIBUTING.md check section and docs/offline-install.md.

Locked decisions from 02-CONTEXT.md that this plan implements:
- "Checks Python version, uv, local model presence, cache dir and data dir permissions (owner-only). Each failure prints the exact fix command. A missing model is a clear message and a non-zero exit, never a silent skip (DOC-01, DOC-02)."
- "Offline: doctor and run make no network calls. No model downloads." Doctor only prints fix commands; it never runs them.
- Install target: a secure-enclave machine, local, shared-screen guidance. Docker path must not regress (Dockerfile sets MINDRIAN_EUREKA_RS_MODEL_PATH=/models/model; the model order below accepts it).
- cli-developer: exit codes 0, 1, 2; `--json` for machines; status words always printed (color is never the only signal); non-interactive.
- python-pro: full type hints, mypy --strict clean on new modules, ruff clean, dataclasses, pathlib, `X | None`, no bare except, Google-style docstrings, pytest fixtures and parametrize.

Answers from the orchestrator (treat as decided):
- OQ-2: missing uv is FAIL.
- OQ-4: the enclave OS and install route are unknown. ASSUMED: the machine may be Linux, macOS or Windows, and may have no PyPI route. Doctor prints fix commands for Linux or macOS and for Windows where they differ, and record this assumption in docs/offline-install.md. All fix texts are offline-friendly (copy a folder, copy a binary, install from a wheel folder).
- Dev tools: pytest, mypy and ruff stay user-level tools. No dev dependency group is added, because it would change uv.lock and the Docker `uv sync --frozen --no-dev` step. The decision is documented in CONTRIBUTING.md (research Open Question 5).

Public API (plan 02-06 consumes these names exactly):
- models.py: `discover_model(explicit: Path | None = None, *, env: Mapping[str, str] | None = None, home: Path | None = None) -> ModelResolution`; frozen dataclass `ModelResolution(path: Path | None, origin: str | None, searched: tuple[str, ...], problems: tuple[str, ...])` with property `ok`; `missing_model_message(resolution: ModelResolution, *, explicit_given: bool = False) -> str`; `os_variants(posix: str, windows: str) -> str`; `missing_files(path: Path) -> list[str]`.
- doctor.py: `run_checks(*, model_path: Path | None = None, load_model: bool = False, env: Mapping[str, str] | None = None, home: Path | None = None, probes: Probes | None = None) -> list[CheckResult]`; `doctor_command(*, json_output: bool, load_model: bool, model_path: Path | None, out: TextIO | None = None) -> int` (prints the report to stdout, returns 0 or 1).

Tooling for every verify command (user-level tools on PATH): `PYTHONPATH=src python3 -m pytest <files> -q -p no:cacheprovider`; `mypy --strict --ignore-missing-imports --follow-imports=silent --python-executable "$(command -v python3)" --cache-dir /tmp/eureka-mypy <new src files>`; `ruff check --select E,F,I,UP,B --line-length 100 --no-cache <new files>`. Strict typing applies to new files only. Never write the short engine codes (regex \b(R[S]|H[S]I)\b) in a string a user can see; the environment variable names keep their literal spelling.
