<objective>
Build the hash check that EXM-01 needs: an expected-hash file format, a command that compares a finished run with it and fails on any mismatch, and a maker that writes the expected-hash file from a real run.

Purpose: EXM-01 says the output hashes of the example run match shipped expected hashes and a check fails when they differ. This plan builds the check and the maker. Plan 04-02 ships the real data and uses both.

Output: a new package `mindrian_eureka.example`, the command `eureka check-example`, the script `scripts/make-example-hashes`, and two test files. The tests need no model and no network.

Decisions made by the planner (no CONTEXT.md exists for Phase 4; these are Claude's discretion):
- P-01: the check is a command of the same tool, so a stranger needs nothing else after `uv sync`.
- P-02: the expected hashes cover the 4 output files `corpus/records.jsonl`, `ranked-pairs.md`, `unusual-pairs.json` and `wording-and-meaning-pairs.json`. They do not cover `manifest.json`, because the manifest holds platform and library text that differs from machine to machine. The manifest is compared field by field instead.
- P-03: the pass rule is exact sha256 equality. There is no tolerance. Environment differences are shown as INFO so that a reader sees why a mismatch can happen.
- P-04: a mismatch where input, settings, model and engine all match is reported as "not reproduced on this machine". The check does not excuse it.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| run folder to checker | A run folder is untrusted bytes. A reader may point the command at any folder. |
| expected-hash file to checker | The file is repo content, but a copy on another machine can be edited. |
| maker to expected-hash file | The maker decides what the project calls "expected". A wrong file hides a drift. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | Run folder edited after the run, then checked against edited hashes | mitigate | X6 compares the bytes on disk with the expected hash and with the hash the manifest lists. Test 8 covers it. |
| T-04-02 | Tampering | Path traversal through `outputs[].path` in a crafted expected file, or a symbolic link in the run folder | mitigate | `load_expected` refuses `..`, absolute paths and backslashes. X1 refuses a link that points outside the folder. Test 12 and test 11 cover it. |
| T-04-03 | Denial of service | A very large JSON or output file | mitigate | `MAX_JSON_BYTES` for JSON; output files are hashed in 1 MiB blocks and the label scan reads each pair file once. |
| T-04-04 | Spoofing | A mismatch that is excused as an environment difference | mitigate | INFO lines never change the result. P-03 and P-04. Test 10 and test 3 cover both sides. |
