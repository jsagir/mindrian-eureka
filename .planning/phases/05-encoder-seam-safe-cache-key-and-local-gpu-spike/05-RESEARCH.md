## Synthesis

**Recommend one GSD phase: add an encoder seam with a proven local CPU/GPU in-process backend and a safe cache key, keep MiniLM as default, and prove Nemotron-3-Embed-1B on the 3060 before any default change.**

### Q1 Can the engine do the embedding itself
Yes, but only in a narrow way today. PROVEN: Eureka already embeds locally with sentence-transformers (MiniLM, CPU); the wording engine takes a bare encode callable and the ranking maths use plain matrices, so a new model needs no ranking change. PROVEN: there is no single seam. At least 7 sites build their own SentenceTransformer (runner.py:84, run/engines.py:234, hsi_engine.py:99, analogy_fitness.py:128, hsi_reference.py:555, pitch_analysis/algorithm.py:134, doctor.py:105). PROVEN: no device, no query/passage prefix, and the cache key lacks dimension, dtype, device and prefix, so a GPU or new model could silently reuse wrong vectors. Smallest change (INFERRED design): one EncoderSpec + Encoder protocol + make_encoder(spec) in opportunity_pairs/encoders.py; first backend = sentence-transformers with device, dtype and doc/query prefix; put the spec fields into the cache key and the manifest; route the two pair engines (runner.py, run/engines.py) through it first and the rest later. Keep MiniLM defaults byte-identical so parity tests and the public example stay green. An HTTP client is NOT needed for the first step. UNVERIFIED: that Nemotron loads through Eureka's class (needs sentence-transformers>=5.4.1 and transformers>=5.2; Eureka pins ST>=5.0,<6).

### Q2 Hosting on the user's own computer
Best path (INFERRED from lanes): run the open weights in-process on each user's own machine with sentence-transformers. No socket, no NIM, no tunnel, so it fits Canon Part 8 and the offline test fixture. Trade-offs: (a) in-process CPU/GPU: private and simple; needs a CUDA torch on the user's PC; on the aarch64 CPU box a 1.14B model is untested and slow (UNVERIFIED, no CPU timing exists). (b) loopback HTTP (llama.cpp, vLLM): works, but the repo forbids sockets today, so it needs a recorded, loopback-only exception; GGUF files are third-party and unaudited; engine swaps can change vectors (single-source report of cosine 0.303 for TEI vs PyTorch, UNVERIFIED). (c) NIM: PROVEN not for the 3060 (NIM on WSL2 officially lists RTX 40/50 only; Embedding NIM 2.4 matrix lists no GeForce card; production serving needs AI Enterprise, about $4,500 per GPU per year). (d) Cloudflare Tunnel to the owner's PC (the saved doc's Option B): sends room text to a third party; breaks Canon Part 8; allow for synthetic data only. Also PROVEN: bit-exact output is shown only on one CPU setup; GPU output will differ slightly, so use a ranking-overlap check, not byte equality, for non-CPU runs. UNVERIFIED: Canon Part 8 was read from a CLAUDE.md summary, not the canon file.
