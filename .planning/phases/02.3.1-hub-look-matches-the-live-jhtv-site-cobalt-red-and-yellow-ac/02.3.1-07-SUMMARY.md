## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The page link and the status chip shared one line in the record panel at 390 px**
- **Found during:** Task 3, visual check (`panel-record-390-light.png`, first take).
- **Issue:** `a.hub-panel-page` is inline-flex (every `a` is) and the `.hub-panel-label` chip is inline-block, so at 390 px the chip flowed onto the link and covered its text.
- **Fix:** `.hub-panel-page { display: flex; inline-size: fit-content; margin-block-end: var(--hub-space-2); }` so the link is its own content-wide line.
- **Files modified:** hub-panel.css. **Commit:** b9aa641.

**2. [Rule 1 - Bug] The phone camera flight could land the selected mark under the bottom sheet**
- **Found during:** Task 3, `test_hub_browser_stage.py::test_widths_fonts_targets_and_reflow` at 320 px (mark at y 357.8 under the sheet top 342) in the loaded regression run; in isolation the mark sat 4 px above the sheet.
- **Issue:** `flyTo` computed the covered part as `stageHeight - innerHeight * .38`, which assumes the stage starts at the viewport top; the sticky header (115 px at 320 px since plan 05 added the toggle) covers the stage top, so the aim was off and the margin was 4 px.
- **Fix:** the visible band is measured (stage box, header bottom, sheet top at most 38 percent of the viewport) and the aim centres the mark in it. Measured after: 320 px mark at y 296 (46 px above the sheet), 390 px at y 234. Stage file 22 passed.
- **Files modified:** hub-graph.js. **Commit:** b9aa641.

**3. [Rule 3 - Probe correctness] Three probe and test corrections**
- `bodyVisible` of the closed legend used `getClientRects`; Chromium renders closed `details` content under `content-visibility: hidden`, which still has a box. The probe uses `checkVisibility()` (falls back to rects). The id link font was read on the anchor, which had the body font: the CSS now sets the mono font on `.hub-catalogue-id a`. The camera "no move" check compared a mid-flight sample with a later one; it now compares the position right before the theme emit with the position after, within one step, after a 2000 ms settle, with a 1e-6 tolerance (the orbit controls drift about 1e-14 per frame).
- **Files modified:** views-look.js, test_hub_browser_views_look.py, hub-catalogue.css. **Commits:** 8885bc2, b9aa641.

**4. [Plan detail] Theme settle waits**
