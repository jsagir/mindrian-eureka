<decisions>
## Decisions

- D-01 (owner) The hub looks like the target site: same paper, ink, cobalt, red and yellow roles, same type scale and weights, same header and section pattern, same finding rows and black pattern band. The owner's verdict overrules the Phase 2.1 colour rule (F3) where it conflicts. Record this as an owner ruling with the date.
- D-02 (rule) UI decisions are ruled by the mos-brand book through its CLI (`node ~/mos-brand/bin/mos-brand.cjs context`, `catalog`, `review`) and cited in the decision. Where the book is silent, propose a segment (do not invent a rule). The book CLI is now version 2.43.0 while the hub copied tokens at an earlier version (the Phase 2.2 token refresh); run `refresh` and `doctor` and record the result; apply `refresh --apply` and the `asset --replace` only if the plan says the owner approved it (the brand-lock reconciliation is an open owner item).
- D-03 (keep) The hub keeps what the owner did not reject: offline, no network, vendored fonts and assets, the data check, the locked page, the reading panel and the three views, the label "candidate, not verified" and a source link on every pair, plain English with no em dash, accessibility floors (13 px label floor, 44 px targets, 3 px focus ring, reduced motion honoured, no ambient motion).
- D-04 (honesty) The black band reads the whole run in plain words and states limits. It must be generated from the run data with sourced numbers only; no invented wording of the kind "the pattern" if the data does not support it; when the run has no clear pattern the band says so or is omitted. No claim of novelty or value.
- D-05 (evidence) Screenshots at 320, 390, 768, 1280 and 1600 px of the new hub, taken by the build, are stored as evidence (public fixture data only; no names). The brand stop is recorded again after the owner looks (plan 02.1-17 stays the home of that record; the planner adds a plan that re-opens it as "pending the owner" on the new look).
- D-06 (privacy) Repo hygiene: no person or partner name from the target in any committed file.
- D-07 (owner, 2026-11-08) Images must be reproducible by anyone, with no image generator (not every user has Codex or any generator). Every picture in the hub is an SVG that the hub's own code generates, deterministically (same run data gives the same bytes; the seed is the pair or record id; no random, no clock, no network, no raster, no `<image>` or external reference), in the closest related style and with the same core idea as the original: the book's flat De Stijl look (paper `#F7F5EE`, 6 px ink frame, heavy ink rules, flat cobalt, red and yellow blocks, thin ink lines at about 55 percent opacity) and the idea of the picture, which is a lead for a person to inspect: two records, the link between them, and how strongly each engine reads the pair. What the figure encodes comes from real data (ranks, scores, term overlap counts, pair class); position and size follow a fixed rule documented in the book segment or a proposed segment; nothing is decoration that implies a claim; yellow only where the book says (a Potential eureka). Each SVG has role="img", a title and a desc in plain words generated from the data (or is marked decorative with an empty alt), and keeps the label "candidate, not verified" in the HTML next to it. A person with an image generator may still replace a picture later; the generator is optional, never required. The book's own image commands (`node ~/mos-brand/bin/mos-brand.cjs image templates`) are references for the style, read only.
</decisions>
