<objective>
Build the ENG-01 parity test. It runs the plugin RS scripts and the repo `eureka-pair-scout` on one fixed synthetic input, in layers, and prints the rank overlap and the score differences.

Purpose: Success criterion 2 of the phase. The layers separate the ranker (proven equal) from the inputs to the ranker (the dense signal and two small items), so a low end-to-end overlap is not misread as a ranker bug.
Output: the test module, fixtures, a golden generator script, and a baseline report taken BEFORE any algorithm change.

Locked decisions from 01-CONTEXT.md that this plan implements:
- Do not vendor the r-and-d script or the original similarity_code files. Use env vars and a golden file.
- Tests run as `PYTHONPATH=src pytest` with a tmp embedding cache path in every test. Any room use is a scratch copy.
- The canonical dense rule is the repo path. The measured overlap is evidence, not a defect to fix by matching the reference. This plan reports the dense-input difference and does not change it.
- No pytest dev group is added (tests run as `PYTHONPATH=src pytest`).

Path ids used in this plan and the report: A = shipped plugin script (sha256 57c18df558d83fbffc8e9f7fda905729d0c0fbfe18a1c370b1db816efa3937f1, legacy scoring only).
